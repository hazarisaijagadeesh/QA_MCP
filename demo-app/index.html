QA Automation Demo

This page shows a simple login flow and explains how an MCP-based assistant can work with a browser to observe actions, generate automation artifacts, and guide test creation.

What this MCP server does

  • Receives a natural-language prompt from a chat or client.
  • Launches a real browser and performs an observed flow.
  • Generates a feature file, step definitions, and page object automatically.
  • Lets the user move from prompt → browser action → test artifacts in one workflow.

General automation scripts vs MCP workflow

General automation scripts

  • Usually hard-coded and tied to one fixed scenario.
  • Script logic is written first, then executed.
  • Good for stable, repetitive paths with known selectors.
  • Requires manual updates when the flow changes.

MCP-based workflow

  • Starts with a plain-language instruction.
  • Uses a tool or agent to observe the browser and generate automation output.
  • Creates reusable test assets such as feature files and page objects.
  • Bridges chat prompts with real execution and test generation.
