QA Automation • MCP Demo
Enterprise-ready workflow

From plain-language prompts to production-ready test automation

This experience demonstrates how a modern QA team can use Model Context Protocol (MCP) to turn a simple request into real browser interaction, automation artifacts, and reusable test structure without manually scripting every step.

How the workflow works

  • A user provides a prompt such as “Open Google and search for automation demo”.
  • The MCP server launches a real browser and observes the flow.
  • It creates structured automation assets such as feature files, step definitions, and page objects.
  • The result is a faster path from intent to executable test design.

Why teams adopt it

  • Reduces handoff friction between business users, QA engineers, and developers.
  • Speeds up test creation for repetitive or newly introduced workflows.
  • Provides a modern agent-assisted approach for digital quality engineering.
  • Helps teams standardize automation practices across environments.
Comparison

Traditional automation

  • Requires manual scripting from the start.
  • Depends on fixed selectors and written steps.
  • Needs ongoing maintenance when flows evolve.

MCP-assisted automation

  • Starts with a simple prompt or request.
  • Uses an agent/tool to observe and interpret behavior.
  • Generates reusable automation assets automatically.
How to use it
  1. Install dependencies:
    npm install
  2. Start the MCP server:
    npm run mcp:server
  3. Send a prompt such as “Open Google and search for automation demo” from an MCP-enabled chat client.
  4. Observe the browser action and review the generated feature, step, and page files.
  5. Run the flow locally with:
    npm run test:showcase
Sample prompts
  • Open Google and search for automation demo
  • Launch the login page and verify the sign-in form
  • Navigate to a demo website and check the main heading
What happens after the prompt is given
  • The MCP tool receives the request and triggers the browser flow.
  • The browser opens, performs the requested action, and captures the observed result.
  • Automation files such as the feature file, step definitions, and page object are generated automatically.
  • You can then review, refine, and run the generated test locally.
